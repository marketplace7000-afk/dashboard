# 1. Обзор проекта

## 1.1 Что это

**Auto Vibe** - веб-кабинет для продавца на Wildberries и Ozon. Клиент - ИП Алешко (автотовары: CarPlay-адаптеры, магнитолы, регистраторы; плюс товары для дома и красоты). Кабинет собирает данные из API обеих площадок и из Google-таблицы клиента и показывает то, чего в кабинетах площадок нет или что там неудобно: единый учет по обеим площадкам, прибыль и ROI по каждому товару с реальной себестоимостью, ДРР по товарам, прогноз закупок, штрафы, BI, ИИ-советы.

Адрес: `https://e-avtovibe.ru`. Вход по паролю или через Telegram Mini App (по списку разрешенных TG-ID).

## 1.3 Ключевые принципы (то, что надо знать, чтобы не сломать смысл)

**Честная цифра важнее красивой.** Клиент проверяет въедливо и ловит расхождения быстрее, чем мы чиним. Если данных нет - пишем «нет данных» и причину, а не подставляем ноль или дефолт. Одна подставленная «правдоподобная» цифра стоит дороже пустой ячейки. В коде это правило зашито в `api/_lib/productEcon.ts`: неизвестное значение - `null` с пояснением, у каждого поля есть признак происхождения.

**Браузер никогда не ходит в WB напрямую.** Лимиты WB считаются на весь кабинет, и запросы из браузера мгновенно дают 429 для всех. Все данные WB собирает фоновый сборщик на сервере раз в 2 часа и кладет в кэш; браузер читает только кэш (режим `cron-only`). Ozon мягче - там `swr`: кэш отдается сразу, обновление фоном.

**Ключ кэша строится из тела запроса.** Сборщик греет данные под ключом из своих дат, браузер и серверные читатели ищут по своим. Разойдутся на день - экран молча пустой, в логах ничего. Поэтому окна дат и тела запросов живут в одном месте (`api/_lib/period.ts` и зеркало `src/utils/period.ts`), и это охраняет проверка `npm run check`.

**Формулы клиента - источник истины по деньгам.** Прибыль на WB считается 1-в-1 по калькулятору клиента (`src/utils/wbProfit.ts`), ДРР - как расход ÷ выручка по **всем** заказам товара (не только от рекламы; кабинет площадки считает иначе, обе цифры показываются рядом). Комиссия - по выбранной схеме работы (сейчас FBS).

**Данные площадок не хранятся в базе.** По замыслу базы нет: кэш в памяти с дампом на диск, история дня и цены конкурентов - в SQLite рядом, введенное руками - в JSON-файлах `av-data/`. Все восстанавливается из API за один-два прогрева.

## 1.4 Стек

- Фронт: React 18 + Vite 5, TypeScript, без UI-библиотек (свои стили в `index.html`/`src`)
- Бэкенд: Node 22, Express (`server.ts`) оборачивает единый обработчик `api/route.ts` в стиле Vercel Functions; запускается через `tsx` без сборки
- Хранилище: in-memory + JSON-дамп, SQLite (`node:sqlite`), JSON-файлы
- Нейросеть: Anthropic API через релей (модель задается `ANTHROPIC_DEFAULT_MODEL`)
- Внешние API: Wildberries (7 хостов), Ozon Seller, Ozon Performance, Google Sheets, Telegram Bot API, ЦБ РФ (курс), публичный `card.wb.ru`
- Хостинг: VPS Timeweb + nginx; Vercel только для релеев

## 1.5 Состояние на 10.09.2026

Работает и проверено на живых данных: сбор по обеим площадкам, себестоимость из таблицы клиента, реклама по товарам (WB и Ozon), комиссии по FBS, цены и расчет прибыли, отзывы с публикацией ответов, бот.

Не работает или ограничено - раздел 8: живая витринная цена WB (публичный API блокирует IP сервера), репрайсер в режиме «только предложения» до согласования порогов с клиентом, окно 14 дней у аналитики Ozon по SKU.

Открытых вопросов к клиенту - раздел 8.4.
