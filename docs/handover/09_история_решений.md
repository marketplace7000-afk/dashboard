# 9. История решений

Зачем этот раздел: половина странностей в коде - это шрамы от конкретных аварий. Без этой истории новый разработчик «упростит» код и наступит на те же грабли. Хронология по датам, самое важное - жирным.

## Май-июнь 2026 - рождение на Vercel

- Платформа стартовала как React-фронт + Vercel Functions, кэш в Vercel KV, крон Vercel каждые 15 минут. Каталог товаров и вся экономика брались из Google-таблицы клиента через Apps Script - таблица тогда и была источником истины.
- Комиссия Ozon зашита как `sales_percent_fbo`: клиент работал по FBO.

## Июль 2026 - переезд на свой сервер

- **Vercel ходит в WB с зарубежного IP - WB банит.** Плюс функции висят все время ожидания WB/Ozon (паузы под лимиты, опрос отчетов), а Vercel считает GB-часы по времени жизни. Решение: **свой VPS Timeweb в Москве**, Express оборачивает тот же `api/route.ts`, крон внутри `server.ts`. Vercel остался ради релеев: Anthropic и Telegram блокируют РФ-адреса.
- **Режим `cron-only` для WB.** Браузер никогда не ходит в WB: лимиты на весь кабинет, и один пользователь мог положить данные всем. Кэш наполняет только сборщик.
- **Асинхронный отчет WB (nm-report) заброшен**: движок отчетов WB стабильно отдает FAILED. Перешли на синхронную воронку `sales-funnel/products`. Побочно потерян дневной график WB - у синхронной воронки нет разбивки по дням.
- 09.07: два инстанса модуля кэша под tsx (ESM для `server.ts`, CJS для `api/`) - крон писал в один `Map`, прокси читал из другого. **Стор кэша повешен на `process`**, а не на модуль. Тот же прием потом применен к очереди отчетов Ozon и к журналу ошибок.

## Август 2026 - месяц невидимой поломки

- **31.07-26.08: дамп кэша не писался на диск.** Выкатка `rsync -a` от root тащила владельца `uid 501` с ноутбука; сервис под `autovibe` терял право записи; пустой `catch` это прятал. После каждого рестарта платформа стартовала холодной и часами показывала пустоту. Клиент видел «ничего не изменилось» месяц. Отсюда правила: **`rsync -rlptz` + `chown`**, **пустых `catch` нет** (журнал `noteSwallowed`), **ошибка записи дампа видна в логе**.
- 05-11.08: цена покупателя Ozon переведена с месячного отчета реализации на отправления (`customer_price`), отставание с недели до суток. Формула ДРР приведена к формуле клиента: расход ÷ **все** заказы, не ÷ выручка от рекламы.
- 11.08: **справочник себестоимости** (`av-data/costs.json`) + синхронизация из основной таблицы «Склад» через сервисный аккаунт Google (клиент попросил не переносить учет в платформу).
- 14.08: даты - **всегда по Москве** (`mskDate`), иначе с 00:00 до 03:00 МСК сборщик и браузер расходились на сутки.
- 17.08: сервер сменил IP из-за фильтрации ТСПУ; домен перепривязан к проекту, не к адресу.
- 26.08 (большой разбор): 55 молчаливых `catch` → журнал; гонка прогрева рекламы WB (`warm-extras` обгонял `fullstats`) - чинится **порядком, а не таймаутами**; постраничный каталог и цены WB; окна дат в одну точку (`period.ts`); `route.ts` разрезан с 1806 до 716 строк; репрайсер этап 2 - **только предложения**, автоприменение запрещено до согласования порогов; каскад 429 у отчетов Ozon (брошенный отчет держал единственный слот) - UUID запоминается и подбирается.

## Сентябрь 2026 - сверка с клиентом по фактам

- 01.09: **поле `nms`, а не `nm`** - из-за одной буквы вся реклама WB по товарам была пустой, ДРР 7% у всех. Ключ Ozon Seller оказался деактивирован самим Ozon - заменен.
- 03.09: **комиссии по схеме FBO/FBS** стали настройкой (`av-data/settings.json`), по умолчанию FBS; ставки WB хранятся по обеим схемам; у Ozon `sales_percent_fbs` приходил в том же ответе и не использовался. Соответствие полей WB проверено на живом ключе: FBS выше FBO.
- 04.09 (аудит по живым данным): **Ozon отдает ZIP с файлом на каждую кампанию, читался только первый** - кабинет видел 3,3% расхода. Клиент вставил колонку «Link» в таблицу - парсер по номерам колонок сломался молча → **колонки по заголовкам**. Витрина WB (`card.wb.ru` v4, поле `product`) совпадает с сайтом рубль в рубль, а «клубная цена» из Seller API - цена подписчика, на 10% ниже. Память СПП Ozon ограничена 14 днями.
- 09.09: лист «Склад» переименован в «Склад Уфа» → вкладка ищется по списку листов; заголовки разнесены по строкам. Дубли Ozon в кабинете - от постраничной выгрузки в браузере → единый источник через сборщик. Отзывы: публикация ответов в WB, «ответить на все». **`card.wb.ru` блокирует IP Timeweb** - витрина и конкуренты с сервера невозможны, нужен российский резидентный выход.

## Решения, которые нельзя откатывать без понимания

| Решение | Почему так |
|---|---|
| WB только через сборщик (`cron-only`) | лимиты на весь кабинет |
| Релеи на Vercel | гео-блок Anthropic и Telegram для РФ |
| Кэш на `process`, а не на модуле | двойная загрузка модулей под tsx |
| `rsync -rlptz` + `chown`, не `-a` | владелец uid 501 ломает запись |
| Нет пустых `catch` | месяц невидимой поломки |
| Окна дат и тела запросов в `period.ts` | ключи кэша обязаны совпадать байт-в-байт |
| `null`, а не дефолт, в экономике товара | клиент принимает решения по цифрам |
| Репрайсер только предлагает | пороги не согласованы, автоцены - отдельное согласие клиента |
| Формула ДРР по всем заказам + вторая цифра «как в кабинете» | оба определения законны, клиент сверяет с кабинетом |
| Отзывы без текста отвечаются шаблоном, не нейросетью | 449 «пятерок» без текста - платить за каждую незачем |
