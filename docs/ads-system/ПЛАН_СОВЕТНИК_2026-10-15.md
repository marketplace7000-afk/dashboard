# Связка «РНП → Конкуренты → Реклама → Цены»: план «Советник 2.0» (15.10.2026)

Черновик на согласование владельцу. Анализ сделан по коду разделов и по советнику, прогнанному на копии прод-базы за 12–13.10.

## 1. Что сейчас и почему советы «не информативные»

Три раздела считают «проблемы» тремя разными наборами правил с разными порогами, и ни один не знает о другом:

| Где | Правила | Чего не хватает |
|---|---|---|
| РНП → «Советник дня» (AdvisorBrief) и «Конкуренты» → «Советник по продажам» (`api/_lib/ads/advisor.ts`) | вчера против среднего за 7 дней: 17 причин просадки | смотрит назад (вчера), не на сегодня; одноразовый «почему», без «что сделать сейчас» и без кнопок; шумит на товарах с 1–3 заказами в день («Карточка хуже продаёт» при 2,6 заказа/день); «Реклама остановилась» сообщает менеджеру о паузе, которую он сам поставил |
| Реклама → Обзор/Товары (`overview.ts`, 9 кодов «узких мест») | за период 7–30 дней | свои пороги, не связаны с советником |
| Реклама → Автопилот (`autopilot.ts`) | 6 видов предложений | не видит конкурентов и позиции; потолок CPC/CPM обещан в описании, но в коде есть только CPO; «сначала худший ДРР» не реализован; норма ДРР 5 % одна на всё, без поправки на категорию |
| Цены (`Prices.tsx`, `Repricer.tsx`) | маржа и ROI считаются **в браузере**, пока лист открыт | сервер видит маржу только по снимку из браузера — на проде советник пишет «свежего расчёта нет», правила автопилота по марже почти не срабатывают; репрайсер без применения; цены по дням не хранятся |
| Обновление данных | цепочка сервера раз в 2 ч **от старта сервера**, без привязки к часам МСК | менеджер в 12:00 не знает, за какое время цифры |

Конкуренты (с 15.10): цены/остатки/рейтинг по 3 проходам в день, позиция WB по дням (с 16.10), отчёты сравнений WB, топ рынка Ozon с медианами категории (ДРР, конверсии) — всё это читает только советник, и только две причины: «конкурент снизил цену» и «у конкурента кончился товар».

## 2. Решение: нужны ли конкуренты для советов

**Да, но не для вопроса «почему вчера просело», а для решений по цене и ставке.** На вопрос «почему просело» в 80 % случаев отвечают наши же данные (остаток, реклама, СПП, скрытая карточка). Конкуренты нужны там, где без них решение слепое:

1. **Цена.** «Наша цена выше медианы подтверждённых конкурентов на 12 %, корзина упала с 9 % до 4 %» → предложить цену с полом по марже. Без конкурентов мы видим только «корзина упала».
2. **Ставка.** Поднимать ставку, когда конкурент дешевле на 7 %+ — деньги в клики без заказов; наоборот, когда у конкурента кончился товар, а у нас запас ≥ 14 дней — окно для +15 %.
3. **Норма ДРР по категории (Ozon)** — медиана категории из «Товаров на Ozon» вместо единых 5 % на всё: для электростанций и для маникюрных аппаратов нормы разные.
4. **Позиция WB** против позиций конкурентов из набора сравнения: упали мы одни (ставка/цена/рейтинг) или вся ниша (спрос).

Честно про сроки: история цен конкурентов копится с 15.10, позиции WB по дням — с 16.10. Сигналы по конкурентам станут осмысленными примерно с 20.10; до этого в ленте они будут помечены «мало истории».

## 3. Целевая связка

```
Источники                       Единый «сигнальный» слой              Куда уходит
РНП (заказы, воронка, остаток,                                        Лист «Советник» в РНП
      СПП, реклама по дням)  ─┐                                      (выпуски 09:00 / 12:00 / 16:00)
Реклама (кампании, ставки,     ├─► signals: товар × код × уровень ─► Реклама → Автопилот (предложения
      расход сегодня)          │   «что случилось · сколько ₽ ·         с кнопкой «Применить»)
Конкуренты (цены, остатки,     │    что сделать · кому»           ─► Цены (рекомендованная цена,
      позиция, рынок)         ─┤                                        пол по марже)
Цены (маржа на сервере)       ─┘                                   ─► Реклама → Обзор «Требует внимания»
```

Один модуль правил `api/_lib/signals.ts` и одна таблица `signal` (mp, sku, code, level, since, данные, действие, статус «открыт / сделано / отложено до…»). Все три экрана читают её; правила из overview.ts и advisor.ts переезжают туда, автопилот берёт из неё задачи. Сигнал живёт, пока условие держится: менеджер видит «3-й день», а не три одинаковых совета.

## 4. Лист «Советник» в разделе РНП

Вместо блока «Советник дня» вверху РНП (убираем) и листа «Советник по продажам» в «Конкурентах» (убираем, ссылка ведёт в РНП).

Листы РНП: **Таблица** (как сейчас) · **Советник**.

**Выпуски три раза в день по МСК** (время — на согласование):
- **09:00 — «Разбор вчера и план дня».** Вчера против 7 дней и против того же дня недели (как сейчас, но с порогами по объёму: причины только у товаров от 2 заказов/день или 3 000 ₽/день); открытые сигналы с «сколько ₽ на кону»; задачи дня по ролям (реклама / цены / контент / закупки).
- **12:00 и 16:00 — «Что изменилось за сегодня».** Темп дня: заказы и расход рекламы к этому часу против среднего к этому же часу (копим внутридневные снимки, через 7 дней база готова; до этого — доля дня); кампании, у которых кончился бюджет/лимит; сгоревшие остатки; карточки, пропавшие с витрины (проход агента 11:40 / 16:40 → перенос на 11:20 / 15:20, чтобы цены были свежие к выпуску); конкуренты, сменившие цену с утра; ДРР дня, вышедший за норму.

Каждый пункт: товар (фото, артикул), цифры «было → стало», ₽ на кону, действие с кнопкой там, где действие есть (ставка/пауза → окно подтверждения автопилота; цена → переход в «Цены» с подставленной рекомендацией; остаток → «Закупки»), кнопки «Сделано» / «Отложить до завтра». История выпусков за 14 дней — можно открыть выпуск 12:00 вчера.

Перед каждым выпуском сервер сам обновляет данные (за 25 минут: РНП-сбор заказов/рекламы за сегодня, синк кампаний) — цепочка привязывается к часам МСК, а не к старту сервера. Внизу листа: «данные на 11:52, цены конкурентов на 11:38».

По желанию: выпуск 09:00 отправлять менеджерам в Telegram (бот уже есть, `api/_lib/telegramBot.ts`).

## 5. Маржа на сервер (обязательное условие для цен и автопилота)

Себестоимость и курс уже на сервере (шаг 2 цепочки cron). Перенести расчёт маржи/ROI с листов «Цены» (LiveWbPricing / LiveOzonPricing) в серверный модуль `api/_lib/margin.ts` с теми же формулами (комиссия, логистика, СПП/соинвест, закупка по курсу); листы «Цены» показывают серверный расчёт; советник и автопилот получают маржу всегда, а не когда у кого-то открыт лист. Попутно начать хранить цену ЛК и цену покупателя по дням в РНП (сейчас только текущий снимок — поэтому «выросла наша цена» считается по заказам и шумит).

## 6. Правила с конкурентами

**Цена (сигналы, советы в «Советнике» и «Ценах»):**
- `price_above_market` — наша цена покупателя выше медианы подтверждённых конкурентов на ≥ 8 % **и** конверсия в корзину ниже своей нормы → рекомендованная цена = медиана − 1 %, не ниже пола (ROI не меньше порога с листа «Цены»); если пол не позволяет — «цена не может быть ниже X, нужна акция/СПП или снижать ставку».
- `price_room` — мы дешевле минимума конкурентов на ≥ 10 % при нормальной конверсии → можно поднять до min − 2 % (прибавка маржи ₽/день).
- `comp_cheaper` (есть) — уточнить: только подтверждённые, ≥ 7 %, с «что делать» по марже.

**Ставка (в автопилот):**
- не предлагать «+15 %», если есть `price_above_market` или `comp_cheaper` — вместо этого задача по цене;
- `comp_out` (конкурент кончился, у нас ≥ 14 дней запаса, ДРР в норме) → предложение +15 % с пометкой «окно»;
- потолок за клик/за 1000 показов из маржи — реализовать, как обещано в описании; «сначала худший ДРР» — отсортировать;
- Ozon: норма ДРР товара = min(5 % бюджета площадки, медиана категории × 1,2) из «Товаров на Ozon»; WB: по позиции — если наша позиция упала, а у конкурентов из набора сравнения нет, → проверка ставки/цены, если упала у всех → «спрос, не трогать».

**Карточка/контент:** CTR и конверсия ниже конкурентов из набора сравнения WB при одинаковой цене → задача «контент» (фото/рейтинг/отзывы), а не ставка.

Применение изменений — как сейчас: только через «Применить» менеджера на сайте. Цены на первом этапе — только совет (кнопки «применить цену» нет), включить применение через то же окно подтверждения — отдельное решение владельца.
