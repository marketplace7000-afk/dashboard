# 6. Деплой и эксплуатация

## 6.1 Как устроена выкатка

CI нет. Код едет с ноутбука на сервер через `rsync`, собирается на сервере, сервис перезапускается. GitHub - только хранилище. Vercel деплоится сам из git, но там живут только релеи.

Перед выкаткой - локальные проверки:

```bash
npm run check
```

Выкатка одной командой (из корня проекта, VPN выключен):

```bash
rsync -rlptz --exclude '.env' --exclude '.env.*' --exclude node_modules --exclude dist --exclude .git --exclude .av-cache --exclude av-data --exclude graphify-out ./ root@200.165.234.229:/opt/autovibe/ && ssh root@200.165.234.229 'cd /opt/autovibe && chown -R autovibe:autovibe /opt/autovibe && npm run build && systemctl restart autovibe && sleep 10 && systemctl is-active autovibe'
```

Что здесь важно и почему:

- **`-rlptz`, а не `-a`.** `-a` от root сохраняет владельца файлов, с ноутбука приезжает `uid 501`, которого на сервере нет. Сервис под `autovibe` теряет право записи, и **молча** ломаются дамп кэша и запись в `av-data`. Это стоило месяца непонятных жалоб клиента летом 2026. `chown -R autovibe:autovibe` после rsync обязателен.
- **`.env`, `.av-cache`, `av-data` исключены.** Выкатка не трогает секреты, кэш и данные, введенные руками. Новые переменные окружения `rsync` не везет - дописывать в `/opt/autovibe/.env` руками.
- **`npm run build` на сервере** собирает фронт в `dist/`; бэкенд не собирается, его запускает `tsx` напрямую.

## 6.2 Проверка после выкатки

```bash
ssh root@200.165.234.229 'bash /opt/autovibe/scripts/smoke.sh'
```

Ждем: `сессия получена`, все эндпоинты 200, залипаний цикла событий 0. Скрипт также показывает последние строки прогрева и ошибки за час.

Принудительный прогон сборщика, чтобы не ждать два часа:

```bash
ssh root@200.165.234.229 'cd /opt/autovibe && P=$(grep -E "^PORT=" .env | cut -d= -f2); S=$(grep -E "^CRON_SECRET=" .env | cut -d= -f2); curl -s -m 900 -o /dev/null -w "cron: %{http_code} за %{time_total}s\n" -H "authorization: Bearer $S" "http://127.0.0.1:${P:-8080}/api/cron/refresh?force=1&secret=$S"'
```

Что смотреть в журнале после прогона:

```bash
ssh root@200.165.234.229 'journalctl -u autovibe --since "30 min ago" | grep -aE "wb-cards|wb-prices|ozon-prices|wb-fullstats|ozon-sku-ads|warm-extras|wb-showcase|sheets\]|costs\]|wb-commissions"'
```

| Метка | Что значит норма |
|---|---|
| `[wb-cards] каталог: карточек N, страниц M` | каталог WB прочитан целиком, M > 1 при N > 100 |
| `[wb-prices] позиций N` | цены WB, N = числу карточек |
| `[ozon-prices] позиций N` | цены и комиссии Ozon |
| `[wb-fullstats] warmed back=7/30 spend=…` | статистика рекламы WB |
| `[ozon-sku-ads] отчет: zip×K … пачек N/N, товаров=T` | реклама Ozon; K > 1 и T - десятки, не единицы |
| `[warm-extras] реклама по артикулам 7д: строк … (WB x, Ozon y)` | таблица рекламы; x и y больше нуля |
| `[sheets] «Склад»: артикул в колонке …, закуп в … (по заголовкам)` | таблица клиента разобрана по заголовкам, не по номерам |
| `[costs] … не найдено N артикулов` | N артикулов справочника нет в таблице - они остались на старой себестоимости |
| `[wb-showcase] образец` | витрина WB; сейчас всегда `снято 0` - card.wb.ru блокирует IP Timeweb (раздел 8) |
| `[wb-commissions] образец ставок предмета` | ставки по схемам; FBS должна быть выше FBO |

## 6.3 Проверки в репозитории (`npm run check`)

Тестового фреймворка нет намеренно: проверки на голом `tsx`, без зависимостей. Каждая закрывает поломку, которая уже случалась:

| Скрипт | Что охраняет |
|---|---|
| `check-periods` | фронт и сервер считают окна дат одинаково; тела запросов не завелись копией - иначе ключи кэша расходятся и экран молча пустой |
| `check-repricer` | пол цены репрайсера считается тем же калькулятором, что маржа на экране |
| `check-ozon-report` | сценарий аварии с отчетами Ozon: брошенный отчет подбирается, а не заказывается заново |
| `check-ozon-zip` | из ZIP Ozon читаются все файлы, а не первый; `ALL_SKU_PROMO` не заказывается; «Заказано на сумму» не задваивается |
| `check-product-econ` | себестоимость ищется по артикулу без таблицы; комиссия строго по схеме FBO/FBS |
| `check-wb-ads` | разбивка рекламы WB по товарам читается из поля `nms` (одна буква стоила недель) |
| `check-wb-showcase` | разбор `card.wb.ru` v4, единицы (рубли/копейки) с якорем |
| `check-sklad-layout` | колонки таблицы «Склад» находятся по заголовкам, в том числе разнесенным по строкам |
| `check-tg-gate` | бот в группе отвечает только на обращение к нему |

## 6.4 Типовые ситуации

**Клиент видит пустые таблицы или нули после рестарта.** Кэш стартует холодным до первого прогрева (~5-10 минут). Если дольше - проверить, пишется ли дамп: `ls -la /opt/autovibe/.av-cache/` и владельца файлов (`autovibe`). Ошибка записи видна в журнале раз в час: `[cache] дамп на диск не удался`.

**Блоки с нейросетью отдают 400.** Почти всегда - кончились кредиты Anthropic. Проверка: `/api/ai/health?force=1` в кабинете (раздел «ИИ-агенты») различает «кредиты кончились», «ключ не принят», «нет связи с релеем».

**WB отвечает 429.** Лимиты WB считаются на весь кабинет. Сборщик ставит cooldown на хост и не долбит дальше; следующий проход через 2 часа доберет. Руками ничего делать не надо.

**Ozon Performance: 429 «максимум 1 активный запрос».** Слот занят отчетом - своим незабранным или запущенным клиентом из интерфейса. Сборщик ждет слот до 10 минут и подбирает брошенный отчет по сохраненному UUID. Если повторяется каждый проход - смотреть `[ozon-sku-ads]` в журнале.

**Сервер перезагрузили.** Сервис поднимется сам (systemd). Известная недоделка: DNS-маршруты после перезагрузки могут вернуться из DHCP (задача в бэклоге, раздел 8).

**Нужно сменить ключ.** `ssh root@200.165.234.229 -t 'bash /root/set-keys.sh'` - спрашивает значения без вывода на экран, делает бэкап `.env`, перезапускает сервис, проверяет ключи.

## 6.5 Локальный запуск

```bash
npm install
cp deploy/env.server.example .env   # заполнить токенами
npm run serve                        # Express на :8080, как на проде
```

`npm run dev` (vite) - только фронт с прокси в площадки напрямую, без серверного кэша; для отладки расчетов достаточно, для проверки сборщика - нет. Публичные эндпоинты WB (`card.wb.ru`) с не-российских адресов отвечают 403.
