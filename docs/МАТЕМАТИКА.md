# Математика платформы Auto Vibe

Документ описывает, **откуда берётся каждая цифра** на всех страницах, **как она считается** и **в каких единицах**. Цель — чтобы клиент мог сверить любое число один в один.

Дата составления: 01.07.2026. Составлено по фактическому коду (указаны файлы и строки).

---

## 0. Как устроены данные (общий принцип)

**Источники:**
1. **WB API** (Wildberries) — 5 токенов по категориям: Статистика, Цены и скидки, Аналитика, Продвижение, Поставки.
2. **Ozon Seller API** — карточки, цены, остатки, аналитика, финансы.
3. **Ozon Performance API** — реклама (Трафареты / Поиск / Брендовая полка). Отдельный кабинет, OAuth на сервере.
4. **Google-таблица закупок** (через Apps Script) — себестоимость, план, маржа, транзит, остатки склада.

**Кэширование (важно для «свежести» цифр):**
| Данные | Где кэш | TTL |
|---|---|---|
| WB (аналитика/статистика/цены/отзывы) | сервер, наполняет **только фоновый прогрев** («cron-only») | 3–24 ч |
| Ozon Seller (цены/остатки/аналитика/финансы) | браузер (localStorage) | 6 ч |
| Ozon Performance (реклама) | сервер | 30 мин |
| Финсводка дашборда | браузер | 6 ч |

**Ключевой нюанс WB:** браузер **никогда** не ходит в WB напрямую — только читает прогретый кэш. Если кэша нет → показывается последний суточный снимок из базы. Лимит WB-аналитики считается **на весь кабинет** (не на токен), поэтому живая аналитика пробивается, только когда лимит свободен.

## 1. Дашборд

Показывает сводку по обеим площадкам. Источник KPI-плиток — живые хуки `useLiveOzon` / `useLiveWb`; финансовый блок (маржа/ДРР/ROI) — `useFinanceSummary`.

**Плитки по площадке:**
- **Выручка по заказам** = сумма заказов за период (Ozon: метрика `revenue`; WB: аналог).
- **Заказов** = кол-во заказов (`ordered_units`).
- **Средний чек** = `выручка / заказы`.

**Финансовый блок (сводно Ozon + WB), файл `financeLogic.ts`:**

| Показатель | Формула | Единицы |
|---|---|---|
| Выручка нетто | `выручка_брутто − возвраты` (по обеим МП) | ₽ |
| **Маржа ₽** | `нетто − комиссии − логистика − хранение − реклама − прочее − себестоимость` | ₽ |
| **Маржа %** | `маржа ₽ / нетто × 100` | % |
| **ROI портфеля** | `маржа ₽ / себестоимость × 100` | % |
| **ДРР** (доля рекламных расходов) | `реклама / нетто × 100` | % |
| **ROAS** | `нетто / реклама` (если реклама > 0) | ×раз |
| **Чистая прибыль** | = Маржа ₽ | ₽ |

Цветовые пороги: Маржа ≥25% зелёный / 10–24% жёлтый / <10% красный. ДРР <10% зелёный / 10–19% жёлтый / ≥20% красный. ROI ≥80% зелёный / 30–79% жёлтый / <30% красный.

**Себестоимость** берётся из Google-таблицы по SKU (ключ в верхнем регистре). Если SKU не найден — он не входит в себестоимость и попадает в предупреждение «нет себестоимости для N SKU».

## 2. Финансы · Ozon P&L (`Finance.tsx`)

Полный P&L строится из **Ozon Finance API** (`/v3/finance/transaction/list` и `/totals`) — те же транзакции, что Ozon отдаёт в финотчёт. Кэш 30 мин.

| Карточка | Формула | Источник (поле) | Единицы |
|---|---|---|---|
| **Выкуплено** | сумма `accruals_for_sale` по операциям `type=orders` | Finance API | ₽ |
| **Возвраты** | сумма `accruals_for_sale` по `type=returns` (отрицательное) | Finance API | ₽ |
| **Выручка (нетто)** | `Выкуплено + Возвраты` (возвраты со знаком −) | расчёт | ₽ |
| **Комиссия МП** | сумма `sale_commission` по orders **и** returns | Finance API | ₽ |
| **Фулфилмент** | сумма `delivery_charge + return_delivery_charge` | Finance API | ₽ |
| **Реклама** | фактический расход **Ozon Performance** за период (`moneySpent`) | Performance API | ₽ |
| **Эквайринг** | операции `services` с `operation_type` = *Acquiring* | Finance API | ₽ |
| **Выплата продавцу** | сумма `amount` по **всем** операциям периода | Finance API | ₽ |

**Критично для сверки:**
- **Реклама Ozon Performance НЕ входит в «Выплату продавцу»** — она биллится отдельно (с рекламного баланса), Ozon не удерживает её из выплаты. Поэтому «Реклама» показывается как справочная строка «вне финотчёта».
- Комиссия считается и для возвратов (не только продаж).
- График «Выкуп по дням» = сумма `accruals_for_sale` по `operation_date` только по `type=orders` (возвраты в график не вычитаются). Дни без данных пустые — финотчёт Ozon по последним дням приходит с задержкой.

## 3. Закупки · Прогноз закупок (`procurementLogic.ts`)

**Суточный расход** (из Google-таблицы, лист `Ozon_wb`):
- `dailyOzon = продажи_30дн_Ozon / 30`, `dailyWB = продажи_30дн_WB / 30`, `dailyTotal = dailyOzon + dailyWB`.

**Цикл поставки:** `цикл = leadTime + packaging` (по умолчанию 52 + 14 = 66 дней; можно переопределить на каждый SKU).

**Тренд-фактор** = `продажи_7дн/7 ÷ dailyTotal`, зажат в [0.5 … 1.5] (ускорение/замедление продаж).

**Сколько заказать (`suggestedQty`):**
```
neededTotal   = средний_дневной_план × targetDays        (нужный объём на целевой период, targetDays=60)
currentTotal  = остаток_Ozon + остаток_WB + склад + транзит_из_Китая
suggestedQty  = max(0, neededTotal − currentTotal)        (если < 100 шт → 0)
стоимость     = suggestedQty × себестоимость
```
Если на месяц есть план продаж — берётся он (÷30), иначе исторический `dailyTotal`.

**Дата заказа (`orderByDate`):** `сегодня + max(0, дни_до_нуля − цикл)`, где `дни_до_нуля = currentTotal / (dailyTotal × трендфактор)`.

**Срочность (`urgency`)** — привязана к циклу (`covered` = дни покрытия с транзитом):
| Статус | Условие | Смысл |
|---|---|---|
| `order_now` | covered < цикл | Заказывать срочно — поставка не успеет |
| `order_soon` | цикл ≤ covered < цикл + буфер | Пора готовить заказ (буфер = max(7; 15% цикла)) |
| `healthy` | цикл+буфер ≤ covered ≤ 90 | Всё в порядке |
| `excess` | covered > 90 и докуп не нужен | Замороженный капитал |
| `no_movement` | продаж нет | Товар стоит |

**Нюанс:** дни покрытия здесь считаются **с учётом транзита из Китая** (в отличие от базового `daysSupply` в таблице, где транзит не учитывается).

## 4. Закупки · Маржинальность (`MarginAnalytics.tsx`)

Маржа берётся из Google-таблицы (лист `Маржа`), хранится как дробь (0.35) → в код переводится в проценты: `round(значение × 1000)/10` (0.35 → 35.0%).

- **Δ за неделю** = `round((тек_неделя − пред_неделя) × 10)/10` (п.п.).
- **Сигнал (severity):**
  - `danger` (Падает): снижение 2+ недели подряд **или** маржа < 0;
  - `warning`: резкое падение ≥5 п.п. за неделю **или** маржа < 10% и падает;
  - `ok`: остальное.

## 5. Закупки · Распределение (`distributionLogic.ts`)

Считает **как разложить уже имеющийся товар** (склад + транзит) между Ozon и WB. Не считает, сколько заказывать (это прогноз закупок).

**Деление транзита из Китая** — пропорционально дневным продажам: `доля_Ozon = dailyOzon / (dailyOzon + dailyWB)` (если продаж нет — 50/50).

**Эффективный остаток после приёмки:** `effStock = остаток_МП + ожидаемый_транзит`.

**Куда везти (доля Ozon):**
- Если одна площадка убыточна (маржа < 0) или без продаж → весь товар на другую.
- Если обе здоровы → взвешенный скор:
  ```
  score_Ozon = 0.5 × скорость + 0.3 × маржа + 0.2 × дефицит
  доля_Ozon  = score_Ozon / (score_Ozon + score_WB)
  ```
  (50% скорость продаж, 30% маржинальность, 20% дефицит до целевого запаса).

**Отгрузка со склада** делится по этой доле; партии < 10 шт округляются вверх до 10. Затем при необходимости добираем из транзита (по будущей нужде, с ограничением ёмкости МП = 30 дней запаса).

**Приоритет строки:** `high` — есть отгрузка и запас < 14 дней; `medium` — есть отгрузка, но не срочно; `low` — только из транзита; `none` — действий нет. Эскалация на ступень выше, если товар кончится **до прибытия ближайшего транзита**.

> ⚠️ **Пункт 3 обратной связи (транзит на склады МП):** сейчас в расчёте участвует **только транзит из Китая**. Товар, уже отгруженный со своего склада на склады Ozon/WB (едет на МП), в расчёт **не входит** — этих данных нет в модели. Для этого нужен источник (лист таблицы «В доставке» или API поставок) — по согласованию.

## 6. Цены (Ozon `LiveOzonPricing.tsx` / WB `LiveWbPricing.tsx`)

**Три типа цены (по требованию клиента, п.4):**

| Тип | Ozon (поле) | WB (поле) | Смысл |
|---|---|---|---|
| **Наша (ЛК)** | `price.price` | `price` | Цена в личном кабинете |
| **Серая · без кошелька** | `marketing_price` | `discountedPrice` | Со скидкой продавца, без кошелька МП |
| **Зелёная · с кошельком** | `marketing_seller_price` | `clubDiscountedPrice` | Финальная цена покупателя (с кошельком Ozon/WB Club) |

**Скидка** = `(наша − зелёная) / наша × 100`.

**Рекомендация цены (Ozon):** `floor(мин_рынка × (1 + коридор%))`, где мин_рынка — наименьший из индексов Ozon: `ozon_index_data` (конкуренты на Ozon) → `external_index_data` (другие МП) → `self_marketplaces_index_data` (свои магазины). Коридор по умолчанию 5%. Защита: рекомендация не опускается ниже `min_price` кабинета.

**Маржа/ROI в таблице цен:** себестоимость и маржа% — из Google-таблицы; `Маржа ₽ = зелёная × маржа%`; `ROI% = зелёная × маржа% / себестоимость` (см. ROI-таблицу в разделе 9). Рекомендация «докупать/стоп/выход» — по статусу ROI.

**Подразделы** «Реальные SKU из кабинета Ozon» / «Каталог WB» — это раскрытие строки: показывают цены конкурентов/другие площадки/свои магазины (Ozon) и все размеры товара (WB). Источник — те же эндпоинты цен.

## 7. Аналитика · Ozon (`LiveOzonAnalytics.tsx`)

Источник — `/ozon/v1/analytics/data` (метрики `ordered_units`, `revenue`).

| KPI | Формула | Единицы |
|---|---|---|
| Заказано | сумма `revenue` за период | ₽ |
| Заказов | сумма `ordered_units` | шт |
| Средний чек | `выручка / заказы` | ₽ |
| SKU в кабинете | `total` из `/v3/product/list` | шт |

**Топ-10 SKU** — `/v1/analytics/data` с разбивкой по `sku`, сортировка по выручке. Колонки: Заказов, Сумма заказов, Доля = `выручка_SKU / общая_выручка × 100`. График «по дням» = массив `revenue` по дням.

> WB-аналитика на этой странице упирается в лимит кабинета WB (см. раздел 0).

## 8. Реклама (`Ads.tsx`)

**Ozon Performance** (`/api/client/statistics/daily/json`, `/campaign`):
| Метрика | Формула |
|---|---|
| Расход | сумма `moneySpent` |
| Выручка | сумма `ordersMoney` |

## 9. Модули · ROI, Акции, Склад

**ROI по SKU (`LiveOzonRoi.tsx`, «Топ-10 по прибыли»):**
```
цена         = выручка / заказы          (фактическая средняя, НЕ прайс — прайс завышен акциями)
комиссия     = цена × sales_percent_fbo%
сборы        = комиссия + эквайринг + доставка_до_покупателя
себестоимость= из таблицы (лист «Склад», col H) ИЛИ оценка (цена × costFactor%, по умолч. 45%)
Прибыль/шт   = цена − сборы − себестоимость
Прибыль·всего= Прибыль/шт × заказы
ROI %        = Прибыль/шт / себестоимость × 100
```

**Таблица целевого ROI по себестоимости** (`roiLogic.ts`) — коридоры: цель / стоп-докуп / выход. Примеры:
| Себестоимость, ₽ | Цель | Стоп-докуп | Выход |
|---|---|---|---|
| 100–200 | 250% | 188% | 130% |
| 300–400 | 140% | 105% | 80% |
| 1000–1500 | 104% | 78% | 66% |
| 5000–5500 | 82% | 63% | 52% |
| 9500–10000 | 58% | 46% | 37% |

(всего 27 диапазонов от 100 до 10000 ₽). Статус: `ok` (ROI ≥ цель) / `warn` (≥ стоп-докуп) / `danger` (≥ выход, новую партию не заказывать) / `stop` (< выход, распродавать).

**Акции и скидки (`LiveOzonPromos.tsx`):**
- Цена покупателя = `marketing_seller_price` → `marketing_price` → `price` (приоритет реальной).
- «Мои акции» = товары, где `old_price > текущая`; скидка = `(old_price − цена)/old_price × 100`.
- «Дешевле у конкурентов» = где мин. рынка < наша × 0.95 (дешевле на >5%), топ-15 по разрыву.

**Продажи и склад (`LiveOzonStocks.tsx`):**
- Остаток = FBO (склад Ozon) + FBS (свой). Продажи/день = `заказы_30дн / 30`. Дней до нуля = `остаток / продажи_день`. Критично при ≤ 14 дней.

## 10. Что стоит держать в голове при сверке

1. **WB-аналитика** может отставать — лимит кабинета WB; показывается последний прогретый снимок.
2. **Реклама Ozon** в «Финансах» справочная — не входит в «Выплату продавцу» (биллится отдельно).
3. **Себестоимость** — из листа «Склад» (B=SKU, H=закуп). Нет SKU в таблице → нет себестоимости → предупреждение.
4. **Цена в ROI/акциях** — фактическая средняя (`выручка/заказы`), а не прайс-лист (прайс завышен акциями Ozon).
5. **Дни покрытия** в прогнозе закупок учитывают транзит из Китая; в базовой таблице — нет.
6. **Кэш**: Ozon — до 6 ч в браузере, реклама — 30 мин, WB — прогрев по расписанию. Кнопка «Обновить из API» форсирует пересчёт.
