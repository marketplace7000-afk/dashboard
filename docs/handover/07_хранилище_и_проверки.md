### `scripts/smoke.sh`

Пост-деплойная проверка, запускается **на сервере**: `ssh root@<сервер> 'bash /opt/autovibe/scripts/smoke.sh'`. Ничего не меняет и не печатает секретов. Первый коммит по логике - `1ca3744 fix(smoke): проверка логинится сама, иначе под авторизацией она слепая`, затем `df52301 fix(smoke): пароль берем из окружения процесса, а не из текста .env` (10.08 скрипт докладывал «пароль не задан», хотя авторизация работала). Мотив: «до этого о поломках узнавали из скриншотов клиента».

Что делает, по блокам:
1. **процесс** - `systemctl is-active autovibe`, `ActiveEnterTimestamp`, `ss -lntp` на порт `${PORT:-8080}`.
2. **вход** - читает `AUTH_PASSWORD` из `/proc/<MainPID>/environ` работающей службы (fallback - разбор `.env`), логинится `POST $BASE/api/auth/login` с сохранением cookie в `mktemp` jar. Отдельно различает «вход выключен» и «пароль не прочитал» пробой `GET /api/auth/check`.
3. **эндпоинты (код · секунды)**, `BASE=http://127.0.0.1:${PORT:-8080}`, с cookie-jar, таймаут 60 с:
   - `/api/auth/check`
   - `/api/meta/status`
   - `/api/bi?days=30`
   - `/api/penalties?days=30`
   - `/api/ads-advisor/by-sku?days=7`
   - `/api/ozon-buyer-prices`
   - `/api/wb-buyer-prices`
4. **залипания цикла событий за час** - `journalctl -u autovibe | grep event-loop` (счетчик + последние 5): именно отсюда берется «network connection was lost» в браузере.
5. **прогревы** - `journalctl` за 2 часа, `grep -E 'warm-extras|cache warm|wb-fullstats'`.
6. **ошибки за час** - `grep -iE 'error|failed|ECONN|timeout'` без `event-loop`.

## 7.2 Хранилище на диске

Два каталога, оба исключены из деплоя: `.av-cache/` (сбрасываемый кэш) и `av-data/` (введенные руками данные + секретный ключ). Базовые пути переопределяются переменными окружения - именно на этом держатся `check-*` скрипты.

### 7.2.1 `.av-cache/upstream-cache.json` - дамп кэша апстримов

- **Модуль:** `api/_lib/cache.ts`. Путь: `process.env.CACHE_DIR || <cwd>/.av-cache`, файл `upstream-cache.json`.
- **Пишет:** `persistToDisk()`, дебаунс `scheduleDiskSave()` - 5 секунд после `cacheSet`. Триггер - любая запись в кэш, то есть в основном крон-прогрев (раз в 2 часа, `CRON_WARM_INTERVAL_MS`), плюс SWR-промахи от запросов пользователя.
- **Читает:** `loadFromDisk()` один раз при импорте модуля (старт процесса). Если файл битый/нечитаемый - флаг `loaded` **не** ставится, и при пустом `memCache` чтение повторится позже (само-восстановление без рестарта).
- **Формат:** плоский объект `Record<cacheKey, { data: any; fetchedAt: number; ttlMs: number }>`, `JSON.stringify` без отступов.
- **Атомарность:** да, асинхронная - `writeFile(CACHE_FILE + '.tmp')` + `rename` из `node:fs/promises` (специально не sync: синхронный дамп вешал event loop).
- **Лимиты:** `MAX_DISK_ENTRY_BYTES = 4 МБ` - записи крупнее на диск не идут, остаются только в памяти (финотчеты WB с `limit=100000` весят ~30 МБ, дамп раздувался до 100+ МБ). `diskSaveInFlight` не дает наслаивать записи. Ошибка записи логируется не чаще раза в час.
- **Особенность:** общий стор висит на `process.__AV_CACHE_STORE__`, а не на `globalThis` - под tsx ESM(`server.ts`)+CJS(`api/`) модуль инстанцируется дважды, и cron писал бы в один Map, а прокси читал из другого (диагностировано 09.07.2026).
- **Альтернатива:** если заданы `KV_REST_API_URL`/`KV_REST_API_TOKEN` - работает Vercel KV (Upstash Redis) вместо диска.
- **Поверх этого же кэша** живет дедуп агентов: `api/_lib/agents/index.ts`, ключ `agent-sent:<key>`, TTL `DEDUP_MS = 20 ч` - сознательно на дисковом кэше, а не в SQLite (после каждого деплоя шли повторы, жалоба 31.07). И учет трат на AI: `api/_lib/aiUsage.ts`, ключи `ai-usage:list:<YYYY-MM-DD>:<random>` (TTL 90 дней) и `ai-usage:agg:<YYYY-MM-DD>` (TTL 365 дней).

### 7.2.2 `.av-cache/history.sqlite` - одна БД на проект

Встроенный `node:sqlite` (`DatabaseSync`), требует Node ≥ 22.5. Через `require('node:sqlite')` в try/catch - при недоступности **все три** модуля деградируют в no-op, ничего не падает. Путь везде одинаковый: `process.env.CACHE_DIR || <cwd>/.av-cache` + `history.sqlite`, каталог создается `mkdirSync(..., { recursive: true })`.

**`api/_lib/history.ts`** - две таблицы:

```sql
CREATE TABLE IF NOT EXISTS daily_snapshot (
  date TEXT PRIMARY KEY,
  ozon_revenue REAL, ozon_orders REAL, ozon_products INTEGER,
  wb_revenue REAL, wb_orders REAL, wb_products INTEGER,
  reviews_unanswered INTEGER, reviews_archive INTEGER,
  ads_total INTEGER, ads_active INTEGER,
  updated_at INTEGER
);
CREATE TABLE IF NOT EXISTS alert_sent (
  key TEXT PRIMARY KEY,
  sent_at INTEGER
);
```
Индексов нет (хватает PRIMARY KEY).
- Пишет `recordDailySnapshot(date, r)` - **по крону**, вызов из `api/_lib/cron.ts:468` после прогрева, дата `mskDate(0)`. Upsert `ON CONFLICT(date) DO UPDATE` с `COALESCE` по каждому полю: частичные `null` не затирают уже сохраненное.
- Читает `getLatestSnapshot()` (последняя строка по `date DESC LIMIT 1`) - `buildSnapshot()` при промахе живого кэша отдает ее с пометкой «на дату X» вместо пустоты.
- `alert_sent` - дедуп алертов (`api/_lib/alerts.ts`): не чаще раза в сутки, чтение `SELECT sent_at ... WHERE key = ?`, запись upsert.

**`api/_lib/competitorWatch.ts`** - своя таблица в той же БД:

```sql
CREATE TABLE IF NOT EXISTS competitor_price (
  date   TEXT NOT NULL,
  nm_id  INTEGER NOT NULL,
  price  INTEGER NOT NULL,
  title  TEXT,
  brand  TEXT,
  rating REAL,
  feedbacks INTEGER,
  PRIMARY KEY (date, nm_id)
);
```
- Пишет `recordPrices(points)` - вызов из `api/_lib/competitorPrices.ts:137` (сбор цен конкурентов, крон/по запросу витрины). Upsert по `(date, nm_id)`, цена округляется. **Лимит: один замер в сутки на артикул** - цель тренд, а не тиковый график.
- Читает `getPriceSeries(nmId, days = 30)` - ряд для графика «как менялась цена конкурента», `getLatestPrices`.
- `rating`/`feedbacks` объявлены в схеме, но `INSERT` их не заполняет.

**`api/_lib/agents/knowledgeBase.ts`** - база знаний агентов:

```sql
CREATE TABLE IF NOT EXISTS mp_knowledge (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  mp         TEXT NOT NULL,
  date       TEXT NOT NULL,
  category   TEXT NOT NULL,
  text       TEXT NOT NULL,
  impact     TEXT,
  action     TEXT,
  source     TEXT,
  dedup_key  TEXT UNIQUE,
  created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_knowledge_mp_date ON mp_knowledge(mp, date DESC);
```
- Пишет `addTheses(items)` - агенты новостей: `api/_lib/agents/mpNews.ts:145` и `api/_lib/agents/marketplaceChanges.ts:118,159` (по расписанию агентов). Дедуп через `dedup_key UNIQUE`.
- Читает `getTheses({ mp, days, limit })` и `thesesAsContext(days = 90)` - последняя ограничена `limit: 60` тезисов, подмешивается в контекст LLM (в т.ч. мини-юристу).
