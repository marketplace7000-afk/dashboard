# 5. Переменные окружения

## Как переменные попадают в приложение

**Сервер (прод, Timeweb `root@200.165.234.229`, `/opt/autovibe`).**
- `server.ts:19` - первая строка `import 'dotenv/config'` → при старте `tsx server.ts` (`npm run serve`) читается `/opt/autovibe/.env` (cwd = `WorkingDirectory=/opt/autovibe` в `deploy/autovibe.service`). Дополнительно systemd сам подгружает тот же файл через `EnvironmentFile=/opt/autovibe/.env` (`deploy/autovibe.service:11`), так что переменные есть и до dotenv. dotenv не перезаписывает уже заданные значения.
- В `api/` и `scripts/` dotenv не импортируется - они рассчитывают, что окружение уже заполнено (сервером, Vercel или systemd).
- `rsync` при выкатке идет с `--exclude '.env' --exclude '.env.*'` (`deploy/DEPLOY_SERVER.md:55,937`), `.env` также в `.gitignore`. Поэтому **новые переменные дописываются руками в `/opt/autovibe/.env`** (`echo 'X=Y' >> /opt/autovibe/.env`), затем `systemctl restart autovibe`. Шаблон для первичного заполнения - `deploy/env.server.example` (`cp deploy/env.server.example .env`, `deploy/setup.sh:989` падает, если `.env` нет).
- Vite при `npm run build` на сервере читает `VITE_*` из того же `/opt/autovibe/.env` и **вшивает их в бандл** - на сервере VITE-переменные задавать не нужно (см. блок «Фронт»).

**Vercel (`aimarket-amber.vercel.app`, тот же репозиторий, роль - релей Anthropic/Telegram и витрина).** Переменные задаются в Project → Settings → Environment Variables (описано в `.env.example:6-7,103`). Vercel-функция `api/route.ts` читает их из `process.env` напрямую. Известные грабли: Vercel сохраняет `# claude-sonnet-4-6` как значение с решеткой, поэтому `ANTHROPIC_DEFAULT_MODEL` санитизируется в коде (`api/_lib/anthropic.ts:91-98`).

**Локально.** `.env` в корне (шаблон `.env.example`); `vite dev` читает `VITE_*` через `loadEnv` (`vite.config.ts:13`), `npm run serve` - через dotenv.

Обозначения в колонке «Где на проде»: **Сервер** = `/opt/autovibe/.env`; **Vercel** = env релея; **Лок** = только локальная разработка.

## Расхождения шаблона `deploy/env.server.example` и кода

**Есть в коде, нет в шаблоне (даже комментарием):**
`ANTHROPIC_PROXY_URL`, `RELAY_SECRET` (шаблон ссылается на него как «уже задан выше» - но строки нет), `TELEGRAM_BOT_USERNAME`, `TELEGRAM_USE_WEBHOOK`, `PUBLIC_URL`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_POLL_TIMEOUT`, `TELEGRAM_POLL_INTERVAL_MS`, `GOOGLE_SA_KEY_JSON`, `GOOGLE_SA_KEY_FILE`, `SKLAD_SCRIPT_URL`, `SKLAD_SHEET_ID`, `SKLAD_SHEET_NAME`, `SUPPLY_TRACKER_SHEET_ID`, `SUPPLY_TRACKER_GID`, `CACHE_DIR`, `COSTS_FILE`, `SETTINGS_FILE`, `REPRICER_FILE`, `COMPETITORS_FILE`, `OZON_REPORT_*` (5 шт.), `AGENT_ADS_WINDOW_DAYS`, `AGENT_ADS_DRR_NORMS`, `AGENT_PROCUREMENT_CYCLE_DAYS`, `AGENT_TRACKER_WARN_DAYS`, `AGENT_TRACKER_URGENT_DAYS`, `AGENT_NEWS_WB_CHANNEL`, `AGENT_NEWS_OZON_CHANNEL`, `AGENT_<ID>_ENABLED`, `WB_TOKEN_COMMON`, `WB_TOKEN_SUPPLIES`, `WB_TOKEN_FINANCE`.

Критично для первичного развертывания: `ANTHROPIC_PROXY_URL` и `RELAY_SECRET` - без них AI на РФ-сервере получит 403 от Anthropic; `SKLAD_SCRIPT_URL`/`GOOGLE_SA_KEY_*` - без них себестоимость из таблицы клиента не подтянется.

**Есть в шаблоне, нет в коде:** `WB_TOKEN_STATISTICS`, `WB_TOKEN_DISCOUNTS`, `WB_TOKEN_PROMOTION`, `WB_TOKEN_FEEDBACKS` - присутствуют только как закомментированные примеры и работают через динамический ключ `api/_proxy.ts:330` (то есть фактически поддерживаются, явного упоминания нет). Прочие расхождения отсутствуют; `KV_REST_API_*` в шаблоне закомментированы и в коде остаются как legacy.

**`.env.example` (корневой, локальный):** содержит `VITE_TELEGRAM_*`, `KV_REST_API_*` как обязательные и инструкции по Vercel-деплою - устарел относительно серверного сценария; не содержит `TELEGRAM_*` серверных, `ANTHROPIC_*`, `RELAY_SECRET`, `AI_DAILY_LIMIT_RUB` и всех путей/тюнинга.

**Секреты в репозитории:** `deploy/.env.server.filled` (не открывался) лежит рядом с шаблоном и, судя по имени, содержит заполненные значения - попадает под `.gitignore` (`.env.*`), но при передаче проекта архивом/rsync его нужно исключить отдельно.
